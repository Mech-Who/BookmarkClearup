## 1. 当前项目概览

BookmarkClearup 是使用 Python 和 uv 管理的本地命令行工具，用于合并 Chrome、Edge 书签。当前支持 Chromium JSON 与 Netscape Bookmark HTML，并支持 Windows、macOS、Linux 的常见 Chrome/Edge 配置路径。

默认操作是 dry-run。用户可以生成两个输入各自可采用的独立结果，也可以显式覆盖基准文件。文件写入使用同目录临时文件、格式验证、原子提交和时间命名备份。

## 2. 当前目录与模块职责

- `main.py`：命令行程序入口。
- `src/cli.py`：参数解析、输入加载、合并统计、格式输出和确认流程。
- `src/entity.py`、`src/functional.py`：书签树模型、解析后的对象操作、遍历和合并。
- `src/bookmark_io.py`：Chromium JSON 读取、外壳保留和备份清理。
- `src/safe_file.py`：JSON 与 HTML 共用的安全原子写入。
- `src/html_io.py`：Netscape HTML 导入导出及时间转换。
- `src/chromium.py`：Chrome/Edge 三平台路径和 Profile 发现。
- `test/`：pytest 测试和脱敏 fixture。
- `doc/ai/`：AI 生成的分析、计划和阶段记录。
- `pyproject.toml`：项目元数据、依赖和 pytest 配置。

## 3. 已确认产品决策

- 相同 URL 出现在不同目录时允许保留多份。
- 同目录同 URL 冲突时保留较新记录，比较顺序为 `date_last_used`、`date_added`，非法值按 0。
- 每个输入生成独立结果；JSON 输出保留对应输入的外壳，HTML 映射为 `bookmark_bar`。
- 默认使用 dry-run；原地覆盖必须交互输入 `yes` 或显式使用 `--yes`。
- 每次覆盖文件只保留一份完整时间命名备份，不自动清理，并提供按时间范围手工清理能力。
- 首个正式版本必须同时支持 JSON 安全合并和 HTML 工作流。

## 5. 当前验证基线

当前全量测试为 `70 passed`。`uv run python -m compileall -q src main.py test` 和 `git diff --check` 均通过，当前提交后的工作区保持干净。

项目目前没有 ruff、mypy、coverage 或 CI 配置，这些属于阶段 5 待办，不影响当前阶段4测试基线。

## 6. 剩余风险与发布门禁

真实 Chrome/Edge 配置的打开、同步和再次保存尚未在隔离账号下验证。JSON checksum 目前只保留原值，不重新计算，浏览器行为需人工确认。

Firefox 尚未适配。工程发布流程、静态检查和性能基准尚未建立。因此当前版本不能宣称正式可发布，只能作为已测试的本地开发版本。

## 7. 当前停点与恢复顺序

本轮开发停在阶段 4。后续恢复时先启动阶段 5，完成工程化和发布基线，再根据真实数据进入阶段 6 性能评估。阶段 0-4 不重复开发，除非回归测试发现缺陷。
